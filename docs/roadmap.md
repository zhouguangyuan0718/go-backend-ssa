# 实施路线与验收

源码级 API、两个 SSA 阶段、原生双架构后端及真实工具链替换均已实现。当前证据与支持边界集中在 [最终验收](m7-qualification.md)，历史实施记录保留在 README 的阶段索引中。

| 阶段 | 已交付 | 主要验证 |
| --- | --- | --- |
| M0 设计 | 显式状态、源码 pin、共享对象和阶段边界 | [设计](design.md)、[状态](state.md)、[流程](pipeline.md) |
| M1 移植工具 | AST/类型化抽取改写、来源哈希、失败即停止的审计 | 491 个生成文件的一致性、固定版本再生成与补丁升级 |
| M2 基础设施 | Universe、位置、符号、IR/SSA、ABI 与实例缓存 | 32/64 位布局隔离、跨实例拒绝、并发与保活 |
| M3 源码到 Built | 完整前端、声明固定点及 Phi 后 SSA | 官方结构/字节差分、语言执行与源码错误报告 |
| M4 导入 artifact | Unified 类型和函数体、版本与闭包哈希 | 三包泛型往返、错误身份拒绝、按需归档输入 |
| M5 EarlyOptimized | 固定原生早期阶段、独立 cache、原生续编译 | 同阶段对照、verifier、真实执行 |
| M6 元数据及原生后端 | runtime/ABI/Aux/静态数据、AMD64/ARM64 代码生成 | 独立 consumer、cgo/race、官方归档与执行对照 |
| M7 交付验收 | 工具链自举、完整规定回归、状态审计与性能基线 | [最终验收与复现](m7-qualification.md) |

“可替换”限定为本次验收的 `go1.27.1`、`linux/amd64` 与 `linux/arm64` 编译路径。库不调用原版编译器兜底；替换驱动遇到未接入选项会拒绝。其他架构、MSan/ASan、完整覆盖率驱动、所有实验特性组合及公开发布路径须另立范围。386 仅用于布局/状态压力验证。

## 验证矩阵

| 维度 | 必须验证的场景 |
| --- | --- |
| 调用隔离 | A→B→A；相同 import path 不同源码；先失败后成功；先取消后成功 |
| 并发 | 多个 Build 交错；amd64/arm64；加入 386 暴露指针宽度缓存；race detector |
| 生命周期 | 同包多个函数；多次后续 Build 后旧函数/类型/符号仍有效；无需 Reset |
| 源语言 | 用特性矩阵逐项覆盖语法、类型规则、泛型、闭包、初始化及运行时构造 |
| SSA | verifier、Phi 前驱、memory chain、Aux 类型、调用签名、不可达块、阶段不变量 |
| 后端消费 | 独立测试 module 仅使用公共包；一个测试后端或受支持子集解释器验证执行结果 |
| 可复现移植 | clean generate/check；规则失配报错；生成器不覆盖手写文件 |
| 语义差分 | 固定输入对比锁定版本官方前端/编译器；规范化差异与语义差异区分 |
| 输出确定性 | 多次调用的规范化图、artifact 和诊断排序；固定依赖内容 |

amd64/arm64 都是 64 位，不能单独证明目标布局隔离。386 首先作为布局和状态压力测试目标，不自动承诺其全部 runtime 特性支持。

Built 阶段未必可用官方 GOSSAFUNC dump 精确截取；测试可以在临时、固定提交的参考编译器中增加只读观测 hook。观测补丁必须独立于库转换规则。文本图相同仅是辅助，执行结果及结构不变量才是语义依据。

测试后端只作为验证依赖，不进入核心库生产路径；没有完成执行验证时，不把 verifier 通过表述为语义正确。

## 后续维护

新增能力先建立官方对照，再修改显式规则或适配，不手改生成算法。上游 patch 更新需保持精确版本校验、重新生成、类型化状态审计、源码差分和受影响的替换工具链验收。发生变化的 compiler 内容会进入 `compile -V=full`，避免复用其他实现的构建缓存。

本地 module 路径为 `go-backend-ssa`，尚未发布远端 module 或工具链发行包。已有本地提交可供审阅；发布和远端操作按用户后续指令进行。

# M3：原生归档读取与显式输入流

本阶段从固定的官方 Go Git 对象生成 `bio.Reader`、`exportdata` 的归档读取函数和 `saferio.ReadData/ReadDataAt`。缓冲、定位、归档长度计算、格式标记检查及错误路径均保留原生函数体。

## 输入边界

`bio.NewReader` 的参数、`Reader.File` 的返回值及内部 `Reader.f` 由 `*os.File` 投影为包含 `Read/ReadAt/Seek/Close` 的接口。生成规则只允许明确指定的函数和参数/返回值位置，确认原始类型确为 `*os.File`，并从该类型推导各方法签名。规则不匹配、重复、分组参数或未审阅方法均拒绝生成。接口之外的操作仍由输出类型检查和效果审计拒绝。

调用方提供流并决定其生命周期；原生 `Reader.Close` 直接调用该流的 `Close`。`MustSeek` 保留相对定位时扣除缓冲字节数以及成功后重置缓冲的行为。定位失败通过已有的诊断异常保留原生消息及底层错误，不退出宿主进程。

`FindPackageDefinition`、`ReadObjectHeaders`、`ReadExportDataHeader` 和 `ReadUnified` 保留原生格式处理；`saferio` 保留对大长度及截断数据的分块读取。归档发现和文件系统搜索未引入。`ReadUnified` 自身只检查对象头格式，不负责与当前编译目标/工具链的对象头做精确匹配；这仍属于后续 noder 导入阶段。

## 验证

- 生成器回归实际编译并运行投影后的程序，验证内存流、实例并行、返回对象身份、底层错误及拒绝未审阅操作。
- 内存输入回归覆盖读入缓冲后的 Offset、相对/绝对/尾部定位、ReadAt、Close 及定位失败的诊断身份。
- 固定 Go 1.27.1/1.27.0 对照从各自 Git 对象独立选取原生函数，仅修改测试导入路径。原生 Reader 接收真实临时文件，移植 Reader 接收内存流；归档测试对照完整读取和分步读取的数据、错误、头记录及剩余字节，并覆盖逐字节截断、单字节破坏、不支持格式、异常大小及超长头。
- 真实官方编译器生成的两个依赖归档经 `ReadUnified` 读取，载荷与独立字节提取结果一致，并继续通过已有的惰性类型加载和泛型源代码检查回归。
- Go 1.27.1/1.27.0 对照均通过：每版本 565 组归档输入 × 3 种缓冲大小，以及缓冲定位和安全读取边界；对照子程序均启用 race。
- 全量 `go test -race -timeout=30m ./...` 通过；之后新增的来源清单断言和真实归档导入连接分别通过定向回归。`syncgo check` 验证全部 453 个生成文件。

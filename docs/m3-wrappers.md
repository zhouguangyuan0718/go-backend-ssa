# M3 原生方法包装函数

本篇记录该批提交时的边界；后续已接通 [原生循环变量捕获改写](m3-loopvar.md)。

本批开放 `noder.Context.MakeWrappers(target)`，迁入 Go 1.27 reader 中整组方法包装函数生成算法。它接在整包去虚化/内联之后，生成接收者适配、嵌入方法和方法值所需的真实 `ir.Func`，并使用上一批的单函数优化驱动完成收尾。

本批仍是原生 IR 阶段。完整源码到 SSA、机器码执行和替换上游编译器的验收尚未完成。

## 实现

`reader.go` 继续由工具生成，新增选择 `MakeWrappers`、`wrapType`、`methodWrapper`、`wrapMethodValue`、`newWrapperFunc`、`finishWrapperFunc`、`newWrapperType` 和 `addTailCall`。保留上游队列消费、去重、类型/方法适用性判定和生成顺序，不增加包装函数模型或配置文件。

此前 reader 的 `need/haveWrapperTypes` 与 `need/haveMethodValueWrappers` 已是实例字段；这次直接消费它们。包装函数和类型的符号标志仍写在同一实例的原生符号上，局部变量和捕获变量归属原生函数。新增适配只有公开入口的 target/依赖归属检查，以及到 `Interleaved.DevirtualizeAndInlineFunc` 的实例调用绑定。

保留的上游行为包括：

- 值接收者的指针包装和 `panicwrap` 检查；嵌入方法的隐式解引用；NotInHeap 类型额外的双指针包装。
- 方法值的 `-fm` 符号、隐藏 `.this` 捕获和 `Needctxt` 标记；复制参数/返回值字段、变参标记及原生函数类型。
- 依据目标架构、动态链接模式、接口调用和可内联性选择尾调用。普通返回、无返回和 OTAILCALL 的结构均沿用原生算法。
- 收尾时 typecheck 函数体，再单函数去虚化/内联，检查展开后出现的方法值（包括闭包内的方法值），最后登记到 target.Funcs。
- 已由普通导入包提供的包装只登记所需声明；本地和新实例化类型按原生规则发出包装。内建 `error.Error` 包装由 runtime 负责。

## 对外调用

在配置好同一图的 runtime、反射、静态初始化和 reader 后：

```go
target := reader.ReadLocalPackage(stub)
reader.Flag.LowerL = 1
reader.Interleaved.DevirtualizeAndInlinePackage(target, profile)
reader.MakeWrappers(target)
```

可运行的公开示例已更新到 [noder/example_test.go](../noder/example_test.go)。独立 module 的消费者也验证了方法值包装和捕获元数据，未使用内部包或替代生产回调。

MakeWrappers 是遵循原生阶段顺序的一次性操作，必须在整包内联之后执行。它修改 target，并消耗该实例的包装队列；不是任意重复调用的幂等 API。发生编译器不变量错误时沿用低层 panic 约定，不保证部分变换后的图可继续使用。不同实例可并发，既有结果保持有效。

## 验证

真实源码覆盖值/指针接收者、嵌入结构/指针/接口方法、普通/泛型/接口方法值、多返回值、无返回值和变参包装。检查生成函数的声明、函数体类型检查、捕获归属、Dupok/Wrapper/Needctxt、nil guard、尾调用和优化后没有临时括号。

另有八实例并发和旧图保留检查、跨 target 拒绝，以及官方 finalized export 数据触发的导入方法值展开：已有导入包装不重复进入当前包的函数列表，原生方法值声明仍完整生成。

上游差分比较完整函数列表、签名、符号标志、所有节点/类型/位置、调用标记、声明/捕获归属、内联树、DWARF 符号和队列清理结果。新增十种配置：386、amd64、mips、ppc64、amd64-newinline、amd64-noinline、ppc64-dynlink、wasm、amd64-runtime、amd64-import。这里的目标配置验证当前 IR 算法，不表示已实现这些目标的完整后端。

runtime 特殊包装暴露出原先参考夹具的初始化顺序不准确：`AutogeneratedPos` 设置得晚于 `typecheck.InitUniverse`。已依据固定上游 `gc/main.go` 调整参考夹具，先设置位置再初始化内建类型，与真实编译器及库一致；没有通过忽略位置差异来放宽比较。

Go 1.27.1 的十种定向差分全部通过。`syncgo generate` / `check` 通过，仍为 253 个迁入文件、`syncgo-m3-v13`；本批未改迁移引擎。

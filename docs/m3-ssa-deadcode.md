# M3 SSA 死代码清理与语句位置

迁入完整原生 `deadcode.go` 和 `numberlines.go`，接通 `numberLines → deadcode` 的算法链。已有的 Copy/Phi 消除、值/块回收及稀疏位置映射直接承担依赖，没有增加简化版清理算法。

`numberLines` 按反向后序遍历选择语句边界，处理不适合停步的操作、空块、前驱行号、循环和多文件范围，建立后续改写使用的 `cachedLineStarts`。原生统计输出保留；debug 文本通过已有 SSA 编译实例的 TraceWriter 输出。

`deadcode` 依次删除死块指向活块的边、删除 BlockFirst 的第二条边、执行 Copy/Phi 消除、计算存活值、清理命名值、迁移语句边界并回收死值/死块。原生的并行边索引、Phi 参数位置和 Uses 更新顺序保持不变。寄存器分配后的调用仍在任何图改写前明确报错。

## 验证

`TestPinnedSSADeadcode` 在 Go 1.27.1 / Go 1.27.0 和 386/amd64/mips/ppc64 四种布局下，对照原生状态和诊断，覆盖：

- 菱形 CFG、不可达前驱、BlockFirst 丢弃的分支及不可达循环；平行 CFG 边对应的 Phi 参数删除。
- 活值、死值与常量缓存回收；命名值的重复项、死条目和空名称清理；空闲链和二次清理。
- 删除语句边界后迁移到同行活值或块末尾；空块、循环、多文件和显式非语句位置；文件范围统计。
- 寄存器分配后调用的拒绝及未变状态。

对照环境为原生位置表注册与库 Universe 相同的 autogenerated 文件，使 file index 输入一致。此处没有归一化掉统计中的文件编号差异。

人工构造的不可达 Copy 环使两版上游在 `copyelimValue` 中发生数组越界：`copySource` 清空当前值的 Args 后，外层继续 SetArg。该失败及修改后的图作为独立原生差分案例保留；本阶段未改写这个上游行为，也不声称任意人工循环值图都可成功清理。

独立 race 测试并发清理八个 64 位实例并保留一个 32 位旧图，检查位置迁移、命名值去重、缓存回收、重复清理稳定性和旧图不变。测试另复算 Uses 并检查 CFG 反向边。全仓库 race 和生成一致性检查通过。

这些测试验证原生 pass 的一致性及图不变量，尚未运行完整 SSA verifier 或目标代码执行。完整 verifier 还需接入原生循环嵌套分析与局部变量合并判定；ssagen 构造、优化流水线和编译器回接仍待完成。

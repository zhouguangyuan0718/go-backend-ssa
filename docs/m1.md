# M1：固定源码审计与最小移植闭环

完成日期：2026-09-29。工具链：官方 `go1.27.1 darwin/arm64`。源码 pin：官方 go1.27.1，`862c888e612ac346c7c4d99c9392bdfd265f33b0`。

## 已实现

| 能力 | 实现位置 | 范围 |
| --- | --- | --- |
| 固定 Git 对象读取 | `internal/port/source.go` | 检查 tag/commit/VERSION，批量读取 blob，忽略来源工作树修改，支持取消 |
| 生产依赖/状态清单 | `internal/port/inspect.go` | 从显式根递归跟踪 cmd/internal、internal、vendor；标准库 API 作为边界 |
| 符号级抽取与改写 | `internal/port/transform.go` | go/types 解析实际选中符号，改写状态、函数调用、函数值、闭包及初始化依赖 |
| 类型和依赖校验 | `internal/port/generate.go` | 原始切片与适配后分别类型检查，显式前序包 importer，拒绝残留 compiler/internal 导入 |
| 状态隔离最小切片 | `internal/types` | 将上游全局驻留表和锁转换为手写 Context 的实例字段 |
| 跨包重定位最小切片 | `internal/cmd/objabi`、`internal/ir` | 实际移植符号编码和链接函数名解析，重定位 objabi 导入 |
| 可复现生成与所有权 | `sync/generated.json` | 记录源、规则、adapter、输出哈希；保护手写/已修改文件；清理过期工具文件 |
| 命令行 | `cmd/syncgo` | inspect、generate、check；Go 定义版本与规则；固定工具链 |

构造函数从类型检查器的 InitOrder 产生，手写 adapter 定义实例的字段和公共入口。规则依赖对象身份，不会将同名局部变量一起替换。初始化表达式的依赖和仅用于初始化的 import 也参与转换。

目录已改为以 `src/cmd/compile/` 为相对根，保留上游文件名和包名；辅助包按来源归入 `internal/cmd/` 与 `internal/go/`。手写 Context 位于 `internal/types/adapter_context.go`。

M1 不把整包视为已移植：`rules.go` 精确选取 7 个真实上游函数和 2 个状态声明。它验证工具机制，不是完整 compiler types/IR 的实现。

## 审计结果

固定输入的审计结果如下；可用 README 命令在本地生成 `_work/inspection-summary.json`：

- 82 个包、681 个文件，52,700 个声明。
- 2,576 个包级变量候选；全部保留显式待分类标记。
- 309,678 条词法引用记录，2,071 条潜在环境/共享设施等审计项。
- 在所选 import 闭包中没有未解析的外部导入。

这是所有生产构建变体的保守并集，包含互斥平台文件及只读候选表。arm64 指令表和 vendored Windows 定义贡献了较多变量，不能据此声称有 2,576 个必须改造的可变会话状态。

完整 JSON 约 100 MB，位于忽略的 `_work/inspection.json`。重复 inspect 输出逐字节相同，摘要包含完整报告 SHA-256。报告保留声明身份/类型语法、初始化表达式/依赖、引用用法、原始构建条件和文件哈希。

审计使用 AST 词法证据，**不提供完整别名分析、动态调用图或全局状态安全证明**。方法间接修改、回调逃逸等仍需结合状态 owner 和后续并发回归审查。只读表也不能仅凭“未找到赋值”自动批准。

## 验证结果

使用：

```sh
GO_SSA_SOURCE_REPO=/Volumes/Disk1/00.Work/00.Code/goallc/go \
GOTOOLCHAIN=go1.27.1 go test -race -v ./...

GOTOOLCHAIN=go1.27.1 go run ./cmd/syncgo check \
  -repo /Volumes/Disk1/00.Work/00.Code/goallc/go
```

结果：全部通过。执行日志在本地忽略的 `_work/go-rules-tests.log`；测试本身保存在仓库，可重跑。

已验证：

- 错误 pin、非 1.27 版本、所有权清单未知字段、取消和源码路径越界拒绝。
- 原始工作树保持不变，即使工作树文件被修改仍读取 pin 对象。
- 状态初始化依赖、跨函数调用、递归、method value/闭包捕获及同名局部变量语义保持；测试会实际编译并执行生成代码。
- 独立 Context 的 map 不共享、输入缓冲区修改不影响返回字符串、旧结果在后续调用后保持有效。
- 缺失依赖、泛型函数、已有 receiver、多名字状态初始化、未知 init 适配和保留字冲突等未支持形式明确失败。
- 人工改动、未登记生产源码、symlink、所有权清单越界和过期文件处理。
- 前后再生成一致、真实符号路径编解码和跨包调用。
- 自动推导路径/导入映射、拒绝越界源路径和非法适配文件名，以及旧布局中工具拥有文件的迁移与人工修改保护。

开发中，初始化依赖测试曾暴露 `var alias = counter` 的根表达式漏改写；修复放在通用 Context 转换规则中，并保留执行级回归。

## 小版本升级演练

对官方 go1.27.0 (`8af21751f066eced273ca3ce49506b366847c623`) 使用同一 Go 移植规则，在临时目标中生成并 check，再升级到 go1.27.1。

演练通过；三份生成 Go 文件内容没有变化，provenance 的源码版本更新。该结果证明当前小切片的升级机制可重复，**不证明复杂前端发生变化时的维护成本**。初始和结束的来源工作树状态一致。

## 当前限制

- 没有 Build API，尚不能从 Go 源码生成 SSA。
- generator 目前每个包一个源码单元，选取顶层非泛型函数和单名字变量；现有 receiver、多文件包和复杂初始化要增加受控规则。
- 选取的是独立算法切片，不自动保留原包所有初始化副作用；Context 单元中出现 init 会拒绝，扩大范围前要审计跨文件初始化。
- 切片目前与机器目标无关；没有证明完整类型 Universe 的 amd64/arm64/386 隔离。
- 输出替换预检和普通 I/O 失败回滚已实现；强制终止不是多文件原子事务，需用 check 检查不一致。
- 完整库的无全局依赖、Go runtime/ABI 兼容和替换原生编译器尚未验收。

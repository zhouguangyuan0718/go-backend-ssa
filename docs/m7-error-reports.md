# M7：原生错误诊断策略

完整 Go 测试目录的首轮替换验证中，800 个用例在驱动拒绝 `-e` 时停止，652 个用例在拒绝 `-C` 时停止。另一个运行用例暴露了 `//line :10` 的语法错误位置差异。相同固定源码的官方 ARM64 基线在修正验收目录权限后已通过。

本批迁入上游 `base.ErrorfAt`、`sameline`、`UpdateErrorDot` 和错误计数，复用已有的原生消息队列、排序、格式化及去重算法。计数、最后一条错误和消息队列均属于当前编译实例。并发报告在队列入口加锁。解析与后续检查共享位置映射：package 声明失败在原生边界停止；非语法类指令错误继续检查其余类型错误。源码错误计数也包含类型 Universe 的诊断；前端正常返回但已有错误时，仍按原生函数队列收集后续闭包及分配错误，不将源码错误误认为所有权异常。达到原生错误数量限制后，通过专用错误退出边界回到库入口，不结束宿主进程；非诊断 panic 仍按原身份传播。驱动负责输出文件清理。

`Options.UnlimitedErrors`、`OmitErrorColumns`、`ActualErrorFiles` 分别接入 `-e`、`-C`、`-L`。语法错误的位置先通过 noder 的原生位置映射，再进入与类型检查相同的诊断队列。`compiler.Error` 同时保留结构化 `Diagnostics` 和独立的原生文本 `Report`；`Error()` 使用该文本。省略列号只影响文本格式，不删除结构化坐标。

已验证：

- 54 组官方文本对照：九类错误 × 两个目标 × 三组参数，包含语法、类型、默认十条错误限制、重复错误、空文件名和虚拟文件名 `//line`、超大 channel 元素与 runtime 闭包分配，逐字节一致；Built/EarlyOptimized 返回同一诊断文本。
- 三组多文件对照覆盖致命 package 错误、多文件语法错误以及指令与类型错误并存。
- 每组失败后编译有效源码成功，先前错误文本保持不变；对照并发运行并开启 race detector。
- 32 个并发错误的数量和排序完整，重复 flush 不重复输出，新实例计数归零。
- 原有 ABI/walk 错误保留回归及低层 base/noder/typecheck/types/walk 测试通过。

完整 Go 测试目录首轮从 1461 个替换失败用例降至 296 个；其中 268 个在提前读取尚未生成的 importcfg 归档时失败，18 个涉及尚未接入的驱动选项，10 个涉及诊断边界。以上是中间结果。修复后的定向上游测试覆盖这 10 个诊断失败及 `//line` 运行用例：ARM64 和原生 AMD64 均为官方/替换各 12 项通过、0 跳过（包含父测试），分别记录 376/378 个包调用本库，耗时 42.823/42.563 秒。最终全库 `go test -race ./...` 和全部 491 个生成文件检查通过。接入错误报告不代表其余驱动选项已全部支持。

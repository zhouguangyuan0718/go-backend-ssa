# M2：基础设施与对象归属

状态：**第一批已实现，M2 整体尚未完成。** 固定官方 Go 1.27.1，提交 `862c888e612ac346c7c4d99c9392bdfd265f33b0`。本批交付可运行的位置设施、诊断收集、目标布局输入，以及支撑后续类型系统移植的多文件生成能力；尚无 Build API。

## 延续的实现要求

- 使用普通 Go module，编译调用在进程内执行，调用之间不共享可变编译状态。
- 上游编译器代码保留 `src/cmd/compile/` 以下的目录、包名和文件名；辅助依赖归入 `internal/cmd/`、`internal/go/`。
- 移植后的 Go 文件直接保存在项目；维护者运行工具升级，使用者无需生成。
- 版本、抽取和转换规则集中在 `internal/port/rules.go`；路径和导入映射自动推导。没有新增人工配置文件，JSON 仅有自动维护的 `sync/generated.json`，审计输出在 `_work/`。
- 保留上游算法与对象定义；同包手写适配使用 `adapter_*.go`。公开包和 gcbridge 共用内部对象，为后续替换原生编译器保留接入路径。

| 内容 | 位置 | 实际能力 |
| --- | --- | --- |
| 多文件包移植 | `internal/port/render_package.go` | 将同包文件一起进行前后类型检查；按包首次出现顺序解析包依赖 |

WholeFile 是文件保留模式，不会自动去全局化。M1 的 Context 转换仍只支持顶层非泛型函数和单名字状态声明；同包可加入独立的无状态文件，但尚不支持为已有 receiver 自动注入 Universe，也不支持将 Context 状态拆到多个源文件。依赖缺失或转换遗漏由前后类型检查拒绝。

## 位置与诊断的所有权

上游 PosBase 包含可写位置和位置表的 fileIndex；因此每次编译必须拥有自己的 base 和 PosTable，不能只新建 table 而复用旧 base。同一个 base 注册到不同 table 会沿用上游检查并 panic。不同实例可并行，同一实例的修改由调用方串行。

`NoPos`、`NoXPos` 改用 `Pos{}`、`XPos{}`。尤其 `(*PosBase)(nil).Pos()` 原先返回共享 `noPos` 的地址，移植后返回新零值的地址，调用方修改它不会污染后续调用。此规则仅接受显式列出的、没有初始化表达式的本包命名 struct 变量；上游新增初始化会导致生成失败。零值指针的跨调用身份不作为契约。

XPos 保持上游紧凑布局，没有加入 owner 字段。**它只能由生成它的 PosTable 解码**；不同表的相同 index 不表示同一位置，工具也不能根据原始 XPos 自动检测误用。未来 Package 结果须连同原表一起保活，禁止跨结果混用。公开别名不承诺任意外部修改的线程安全。

Collector 在 Add 时保存文件名、行列和消息，不持有可变 base；Diagnostics 返回复制后的 slice，后续收集和其他编译不修改旧快照。深层编译器错误到 Collector 的适配将在移植 base/类型检查时接入，目前不引入 stdout、退出进程或全局回调。

## 类型、符号和阶段状态的确定边界

以下是下一批的实现设计，**尚未定义假的 Type、Pkg、Sym 或 Universe 来满足编译**。

| 对象/状态 | 所有者与接入方式 |
| --- | --- |
| 目标大小 | Universe 保存不可变 target.Layout；PtrSize/RegSize/MaxWidth 不再是包变量 |
| Type 与派生缓存 | Type 添加私有 Universe 引用，保留上游 extra、width、flags 和 cache 字段；构造函数由 Universe 提供，已有方法通过 owner 取得布局 |
| Types/预声明类型/形状 | 每个 Universe 独立初始化；不共享包含 Type 指针的表、map 或 slice |
| Pkg/Sym | Universe 持有 pkgMap、nopkg、LocalPkg 等；Pkg 关联 Universe，Sym 经 Pkg 找到 owner；禁止把外部编译的 Pkg/Type 接入本图 |
| nil Pkg 查找 | 显式 Universe 入口解析到本实例 nopkg；单独的 nil receiver 无法推导 owner，调用点必须改写，不保留隐藏 fallback |
| 类型与 IR 循环 | 保留 types.Object 接口的 Pos/Sym/Type 契约，由真实 ir.Node 实现；不以空接口或占位 Type 消除依赖 |
| 链接符号 | 保留对象身份需求。审计 Pkg.Pathsym、Sym.LinksymABI 及 obj.LSym 的真实依赖后接入；不创建名称相同的简化 LSym 并做 unsafe 转换 |
| 包/函数/阶段 Context | frontend 实例化并连接依赖；CurFunc、Target、延迟队列和 callbacks 属于本次阶段；底层包不反向导入 frontend |

Type/Pkg 的 owner 是结构性改造，需要 go/types 对象定位的字段注入和已有方法转换，并对构造、composite literal、回调、方法表达式、跨 Universe 输入补充执行测试。当前 whole-file 能力只负责保留已有方法，不能把这一步视为已完成。

目标配置常量取自固定上游的 `cmd/internal/sys/arch.go` 和 amd64/arm64/x86 的 `galign.go`；当前验证指针宽度及实例隔离。**这不是完整 Type 大小/对齐测试**，也不代表已能编译这三个目标。Slice/String 布局、递归/延迟布局和 ABI 寄存器分类将接入上游类型算法后再验收。

## 原生消费者与 Aux 边界

已阅读固定提交中的关键直接依赖，范围如下；不是完整反向调用图：

| 源码 | 约束 |
| --- | --- |
| `types/type.go` 的 Object、Type、Registers | Object 引用真实 Sym/Type；Registers 会触发 CalcSize，读取可能伴随缓存写入 |
| `types/pkg.go`、`sym.go` | pkgMap/nopkg/LocalPkg 和 obj.LSym 路径需要显式归属 |
| `ssa/location.go` 的 LocalSlot | 直接持有 *ir.Name、*types.Type 和分裂槽；不能只公开名称字符串 |
| `ssa/op.go` 的 AuxNameOffset/AuxCall | Name 和 Fn 指针须共享身份；reg、abiInfo 私有，需要同包访问接口 |
| `ssa/rewrite.go` 的 Aux | marker 接口需由同一套对象实现，不能复制同名结构代替 |
| `gc/main.go` 的目标初始化 | PtrSize/RegSize/MaxWidth 来自架构配置；未来 bridge 把配置传入 Universe |

本批独立 consumer module 只通过公开包编译，并证明 position.Pos 与 gcbridge.Pos、双方 PosTable 是同一种类型。没有在 Go 源树中替换 cmd/compile，没有验证 native tail 或 bootstrap。后续 Type/IR/ABI 接入面需要同样的消费测试，再在隔离的官方源码树里完成编译器接回。

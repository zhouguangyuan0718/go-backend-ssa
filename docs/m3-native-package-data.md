# M3：原生包数据收尾

本阶段接通固定上游 `gc.dumpdata` 和 `dumpembeds` 的完整函数体，公开 `gc.Context.DumpData`。原生顺序保持为 GC 符号、插件表、嵌入数据、map 零值、函数值符号和函数 GC 辅助数据。调用者须先完成类型/函数固定点及 DWARF 收尾；完整包驱动仍未迁入。

## 文件输入与实例归属

`staticdata.Context.OpenFile` 显式返回 `io/fs.File`，保留原生读取、关闭和元数据检查。未配置时返回错误，不读取进程文件系统。大文件仍保留原生 `LSym.FileInfo`，对象写出通过同一图的 `obj.Link.OpenObjectInput` 再次打开；调用者须在两阶段提供不变的内容。

`fileStringSym` 保留 1 KiB 边界：小文件读入符号，大文件按原生算法生成哈希和文件引用。只读数据共享，`[]byte` 数据独立。原生两条分支使用不同的 `hash.Sum32` / `hash.New32` 算法，这一点未统一或改写。文件过大、非普通文件、读取失败和读取期间长度变化均保留原生错误；成功打开的输入在各退出路径关闭。

完整 `staticdata/embed.go` 保留 string、`[]byte`、`embed.FS` 数据格式、目录补齐、去重、排序、内容哈希和重定位。嵌入配置属于当前 IR 的 Flag；不存在进程级输入缓存。生成器仅将已审计的 `os.Open` 返回值收窄为 `io.ReadCloser` 或 `io/fs.File`，核对完整接口方法签名及原始参数/错误类型，不允许返回宿主文件句柄或增加其他文件系统调用。

## 阶段边界

`DumpData` 拒绝未绑定图、待编译函数、失败 worker、已编号或已收尾对象。阶段开始即消耗本次收尾入口；输入异常或原生诊断阻止设置归档头。独立编译实例仍可继续。`AddGCLocals` 保留供低层对象使用，但同一图不能再重复调用完整数据收尾。

独立 consumer 的源码到归档验证已改为调用生产 `DumpData`。嵌入数据测试目前构造真实原生 IR 声明和显式配置，尚未声称完整源码导入器已处理 `import "embed"` 和构建系统的嵌入配置。

## 验证

- 文件元数据 provider 的生成、并行实例与拒绝未审计操作测试。
- 8 组并行编译实例，0/1/1024/1025/8192 字节边界，关闭次数和读取错误身份；4/8 字节、大小端下的 `embed.FS` 排序、哈希和布局。
- 包级插件表、257 字节 map 零值、大小文件的 string/`[]byte` 数据、实际对象写出、保留输出和独立实例、失败后拒绝复用。
- Go 1.27.1 和 Go 1.27.0 共 34 组原生对照通过：每个版本 4 组静态数据布局快照，以及 13 组 AMD64 完整归档字节比较，包含优化、race、ABI、DWARF、分离归档和四 worker 配置；官方 archive/goobj reader 回读检查同时通过。
- 全量 `go test -race ./...` 通过，包含独立 consumer；447 文件生成一致性复查通过。

完整包级固定点、源码 Build 驱动、链接执行、ARM64 后端及替换/自举继续作为后续验收，不以本阶段的数据或归档差分替代。

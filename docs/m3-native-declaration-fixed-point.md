# M3：原生声明固定点

`gc.Context.CompileDeclarations` 接通上游 `gc.Main` 的完整声明固定点。入口位于前端优化、ABI 包装和逃逸分析之后，数据收尾之前；它不是完整命令行 `Main` 或源码 Build 驱动。

## 保留的原生顺序

先执行 `reflectdata.WriteBasicTypes`，随后按上游顺序反复执行：

1. 写出待生成的运行时类型。
2. 逐个处理新增全局变量、常量和类型声明。
3. 逐个准备新增函数，包含类型描述符生成的相等性/哈希等辅助函数。
4. 排空原生并行编译队列，然后重新检查类型与声明。
5. 完成 DWARF inline fixup，清空 fixup 状态并关闭后续 inline DIE 生成，再次循环；该步骤可能产生新的类型。

直到上述工作全部为空才退出。`DumpData` 随后完成包数据收尾，`WriteArchive` 输出最终归档。

## 源码边界与归属

生成器以导入路径和调用成员定位 `Main` 中从 `reflectdata.WriteBasicTypes` 到 `base.Timer.AddEvent` 的完整连续语句段，保留其中完整的原生循环。显式输入为原有局部变量 `symABIs` 和 `profile`，类型从原生声明及已核验的构造函数签名推导。

抽取检查保留原始词法对象身份，拒绝未声明捕获、变量遮蔽、输入变量存储的修改或取地址、区间局部变量向外逃逸，以及不受支持的 return/defer/goto/闭包边界。当前只接受指针输入，不猜测值类型复制的语义。来源文件和额外构造函数签名均进入生成清单。

原生 `enqueueFunc` 与 `compileFunctions` 函数体仍保留；调用点通过同签名的阶段适配检查实例归属、worker 配置和失败状态。worker 中的 panic 在加入全部 worker、恢复并行标志后传回调用方，失败图不能继续数据收尾。

`CompileDeclarations` 对同一上下文只运行一次，要求未手动入队的已初始化 backend。不能先自行写出全局变量或预先排队，再调用本入口。成功后不再接受额外排队或重复声明编译。不同编译实例可以并行，旧归档由调用方持有。

## 验证

- 生成器验证连续语句保留、输入签名来源、显式捕获和边界拒绝；原生函数保留与适配调用的测试覆盖真实函数体执行、失败前停止、错误签名和遗漏定义。
- 8 组并行源码编译：包含有方法的递归结构、数组字段、全局变量、接口转换、方法值和相等比较。确认新增运行时辅助函数全部生成机器码、类型描述符和全局存储写出、DWARF 状态清空，随后完整归档可保留且不受下一实例影响。
- 外来 ABI、预入队、重复入口和 worker panic 的拒绝与恢复边界通过竞争检测。
- 定向 DWARF 回调在收尾时登记此前不存在的类型，确认循环继续生成描述符及新的机器码辅助函数。
- 独立 consumer 已改用生产固定点入口。

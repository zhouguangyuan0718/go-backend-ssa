# M3：原生 SSA 阶段配置与初始化

本批接通固定上游 `compile.go` 的阶段表、选项解析和阶段顺序校验，为完整 `Compile` 驱动准备实例状态。59 个阶段、42 条顺序约束、`PhaseOption`、`pass.addDump` / `String` 以及原生 `init` 校验均从上游生成。原有仅选择 `checkEnabled` 的延后初始化声明已移除。

## 编译实例与初始化

每个 SSA `Context` 独立持有阶段表、阶段顺序表、检查器开关与随机种子、intrinsics/build 标志、`BuildDump` / `GenssaDump` 和各阶段转储映射。公共 `ssa.Context` 可直接调用原生 `PhaseOption`。

`NewContext` 在绑定并校验类型、IR、ABI、目标和编译服务之后初始化阶段表。调用方需要在创建 SSA context **之前** 配置类型 universe 的实验选项；阶段表按照原生初始化表达式捕获 `SIMD` 和 `PreemptibleLoops`，其他算法仍从同一 universe 读取自身需要的实验选项。创建配置或应用选项不会重新初始化阶段表。

操作码元数据实例不需要类型 universe。生成器新增显式 `InitGroup`：原有元数据初始化和阶段初始化分别生成 receiver 方法，各组保留 Go 的变量依赖顺序及随后按文件排序的原生 `init` 顺序。普通 `NewContext` 执行两组；元数据构造只执行元数据组。

分组审计通过类型对象识别包状态，拒绝初始化表达式、原生 `init`、被调用的本地函数/方法及回调对其他组状态的访问；无法解析的间接调用、接口派发和没有可检查函数体的本地调用同样拒绝。保存函数值不执行其函数体，因而阶段表可以保存稍后才执行的阶段入口。值类型的 owner 在其所属组初始化前绑定。命名组仅用于 receiver 初始化，不能复用普通 constructor 名称、原生方法名称或延后未选择 `init` 的规则。

原生 `log.Panicf` 路由到实例诊断输出，随后以原消息 panic。缺省输出为 `io.Discard`；没有进程级 logger 或标准错误流回退。

## 验证范围

- 生成器测试执行独立初始化组及并发实例，验证跨文件变量依赖、原生 `init` 顺序、值对象 owner 和保存回调的实例归属；拒绝直接、间接、方法和回调形式的跨组依赖、未知间接调用及名称冲突。
- SSA 独立测试覆盖两个实验开关的四种组合、全部阶段入口与顺序约束、检查器 seed/poset 联动、正则与下划线选项、必需阶段禁用错误、转储映射及 8 个并发实例；旧实例和无类型的元数据实例保持独立。
- 同一源码快照操作序列对比 Go 1.27.1 和 Go 1.27.0，覆盖 386/amd64 与四种实验开关组合；记录所有阶段的入口名称和选项、完整顺序表、所有选项操作的返回文本及状态，包含帮助、非法正则、未知阶段和必需阶段保护。
- 独立 consumer 使用公共 `PhaseOption` 和 `BuildDump`，并检查不能禁用必需的寄存器分配阶段。

本批验证结果：两版上游 × 8 种配置，共 16 份阶段配置快照全部一致；`go test -race -count=1 ./...` 通过，包含独立 consumer。随后新增的接口调用/无函数体拒绝分支也通过对应生成器 race 测试。最终 `syncgo check` 确认 398 个生成文件与当前规则一致。

该提交还没有接通完整 `Compile` 调用循环，也未实现源码到 SSA、完整 ssagen、目标指令输出及替换/自举闭环。下一步需要保留原生计时、内存统计、panic 阶段诊断和 dump 命名/写入逻辑，并通过显式服务绑定这些主机操作。

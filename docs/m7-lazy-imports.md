# M7：按需加载 importcfg 归档

上游 Go 测试会在同一份 `importcfg` 中登记随后才生成的多个包。替换驱动此前在编译前读取全部条目，导致 `bug369.go` 的第一轮编译就尝试打开尚未生成的 `test/fast.o`，以及 267 个类似用例失败。原生编译器只打开实际导入的归档。

`Request.ImportLoaders` 现在按规范包路径声明显式归档提供器。原生导入器需要该包时才调用提供器，每个编译实例最多调用一次，结果与错误均缓存；返回的字节被复制为当前实例的输入快照。既不被导入、也不被 artifact 校验引用的归档不会打开。提供器接收本次编译的 context，取消、原始错误与 panic 保持可识别。`compiler.Error.Unwrap` 保留输入提供器错误，供 `errors.Is/As` 检查。

预加载 `Imports` 保持可用，同一路径不得重复出现在 `Imports`、`Artifacts`、`ImportLoaders` 中。SSA artifact 的严格依赖校验也使用同一解析器：校验要求的 native archive 会加载并核对 SHA-256，错误版本仍拒绝；后续导入重用同一快照。Build 输出的依赖身份来自实际加载的数据，不依赖调用者维护额外哈希。

驱动为每个 `importcfg` 条目提供读取函数，保留文件路径和原始读取错误；库不自行查找或打开宿主文件。

已验证：

- amd64/arm64 × Compile/Built/EarlyOptimized 六组，按需和预加载方式生成的完整归档或 SSA artifact 逐字节相同。
- 未使用的未来输出不触发读取；实际依赖每次编译只读取一次；调用者的 map 和字节不被修改，保留结果不引用提供器后续修改的数据。
- 混合 artifact/native 依赖闭包、错误哈希拒绝、原始错误、取消、panic 身份和八个并发独立编译均通过 race 验证。
- 原生 AMD64 上游 `alias3`、`closure3`、`closure5`、`ddd2`、`bug369` 用例：官方与替换均 6 项通过、0 跳过（包含父测试），383 个包调用本库，耗时 41.542 秒；明确核对 `test/slow`、`test/fast` 的成功编译记录。

ARM64 相同导入用例也为官方/替换各 6 项通过、0 跳过，381 个包记录到本库，耗时 44.64 秒。完整 Go 测试目录中，官方为 2670 项通过、59 项跳过；替换工具链记录 2651 项通过、59 项跳过，余下 18 个叶子测试均在未支持的 `-live`、`-l=4`、`-smallframes`、`-B`、`-dynlink`、`-linkobj` 入口停止。此前 268 个归档读取失败全部消失。全库 `go test -race ./...` 通过。
